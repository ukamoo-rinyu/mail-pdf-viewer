# Feature Specification: 工事図面管理（発注前チェック・変更記録台帳・変更契約／竣工図の支援）

**Created**: 2026-09-29

**Status**: Implemented（業務ルールの一部は仮決め。`STATE.md` 参照）

**Input**: 利用者から渡された実装仕様書「工事図面管理機能 実装仕様書（Claude Code用）」と試作スクリプト `tools/check_drawings_prototype.py`。建設工事ごとに図面を台帳化し、①発注前の目次・表題欄の照合、②施工中の変更指示の記録、③変更契約の未反映一覧と変更図面の版登録、④竣工図に反映すべき変更のチェックリストを、図面単位で一か所に集める。

**考え方**: ツールは人の見落としを拾う役割。判定は「エラー」ではなく「要確認」として出し、最終判断は人が行う。

## User Scenarios & Testing

### User Story 1 - 発注前に図面セットを点検する (P1)

担当者は発注前の図面セットPDF（1ページ目に図面リストの目次）を開き、目次と各図面の表題欄が合っているかを一覧で確かめる。

**Acceptance Scenarios**:

1. `python -m drawings.checks <PDF> --layout layouts/toshiseibi_A1.json [--csv 出力.csv]` で、ページ・図面番号・図面名称・縮尺・判定の一覧を画面に出し、CSV（UTF-8 BOM付き）でも保存できる。
2. 判定ルール: 目次の番号重複・名称重複・名称空欄、図面番号が読めない・目次にない・欠番の番号、名称不一致（似ている度合いと「番号の付け違い？」の併記）、番号重複ページ、縮尺・製図年月・総枚数の空欄、総枚数の不一致、工事名の不統一、凡例の参照先なし・参照先が欠番、目次にあってPDFにない図面（参考・件数のみ）。
3. 表題欄・目次の位置は様式設定ファイル（`layouts/*.json`）で持ち、ページの大きさとの比率で換算する（A1原寸とA3縮小版の両方を同じ設定で読む）。
4. 実図面（A1・11ページ）で: 目次202行、欠番2件（314・326）、11ページすべてが目次と一致、総枚数空欄11件、凡例の(22)が目次になし・(8)(20)が欠番、を検出する。
5. 間違いを仕込んだ版で: 名称1文字違い（2～12階平面図）、番号の付け違い（p9: 303／正しくは304）、縮尺の空欄（p10）を検出する。
6. 試作スクリプトと同じ結果（各ページの読み取り値・判定の種類と件数）になる。

### User Story 2 - チェック結果を画面で確かめる (P1)

**Acceptance Scenarios**:

1. 開始画面の「図面セットとして開く」、またはタブの右クリックメニューから、様式を選んでPDFを図面セットとして開ける。
2. 左に結果一覧（ページ・図面番号・図面名称・判定件数、その下に指摘）、右にPDF。要確認のある行は色で区別し、「要確認のみ」で絞り込める。
3. 一覧をクリックするとそのページへ移動し、指摘の範囲（表題欄の該当欄、凡例の参照番号、目次の行）を赤枠で強調する。「指摘箇所を拡大して表示」がオンなら拡大して中央に出す。
4. 「CSV出力」「HTMLレポート」で保存できる。
5. 既存のメール束PDF・一般資料PDFは従来どおり開ける。同じPDFを図面セットとして開くと、そのタブを置き換える。

### User Story 3 - 施工中の変更指示を図面ごとに記録する (P2)

**Acceptance Scenarios**:

1. 工事フォルダを開くと `工事台帳.json` を読む。なければ工事情報と発注図PDFを入力して新規作成し、目次から図面一覧を、各ページの表題欄から「発注」の版を自動で作る。PDFは工事フォルダ内に置き（外にあればコピーするか尋ねる）、台帳には相対パスで記録する。
2. 図面を選ぶと、その図面の変更記録が時系列で表示される。変更記録は、記録日・指示日・きっかけ（種別・番号）・内容・理由・決定者・指示方法・対象図面（複数）・図面上の箇所・状態を登録・編集できる。図面上の箇所はPDF上をドラッグして指定する。
3. 変更記録の一覧を、状態・図面・期間で絞り込める。
4. 登録・編集・状態変更は、日時・操作者つきで履歴に自動で残る。
5. 保存のたびに上書き前の内容を `工事台帳.bak.json` に残す。読み込み後に他で更新されていたら警告し、上書きするか読み込み直すかを選ばせる。

### User Story 4 - 変更契約・竣工図の作成を支援する (P2)

**Acceptance Scenarios**:

1. 変更契約用一覧: 状態「指示済」の記録を図面別に HTML・CSV で出力する（変更理由の下書きつき）。
2. 変更図面の登録: 変更図面PDFを新しい版（既定は「変更契約N」）として登録する。登録前に各ページの表題欄を台帳の図面一覧と照合してチェックし、反映した変更記録を選んで「変更契約に反映済」にする。
3. 新旧対照: 同じ図面の前の版と最新の版を別ウインドウで左右に並べる（スクロール連動、差分の自動検出はしない）。
4. 竣工図チェックリスト: 竣工図に反映すべき全変更（契約変更の有無を問わない）を図面別に一覧化し、チェックを付けると「竣工図に反映済」になる。HTML・CSVで出力できる。

## 仮決めした業務ルール（利用者の確認待ち）

- 状態: 協議中（追加）／指示済／変更契約に反映済／竣工図のみ反映（契約変更しない軽微な変更）／竣工図に反映済／取消（追加）。
- きっかけの種別・指示方法の選択肢（入力欄は自由記入もできる）。
- 竣工図チェックリストの対象は「協議中」「取消」以外。変更契約用一覧の対象は「指示済」のみ。
- 目次の行についての指摘（番号重複など）は、ジャンプできるよう目次のページ番号を持たせる（仕様書では「目次全体なら None」）。

## Out of Scope
